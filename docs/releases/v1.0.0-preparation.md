## Archive contents and model roles

The candidate is a Git source archive, not a wheel, installed environment or
prebuilt Docker image. It contains:

- README, MIT LICENSE, both citation files and this preparation record.
- Source modules and the existing synthetic test suite.
- `pyproject.toml`, top-level requirements, `training/requirements-nn.txt`,
  `prediction/requirements-tf210.txt` and `docker/requirements-runtime.txt`.
- Both root Dockerfiles, `.dockerignore`, and the `docker/` guide, example YAML
  and smoke-test script. Docker images retain the pooled-model default. Docker
  builds, GPU execution, training and inference were not run in this preparation.
- The existing pooled deployment model and its run metadata/checksums, plus the
  exact saved HEK293T evaluation checkpoint, run metadata/checksums and
  `configs/HeLa_HEK293T_evaluation.yaml`.
- All 17 prepared human reference BEDs, the 19-entry portable catalog,
  provenance and checksums, and the four existing mouse RMBase source archives.

The added evaluation YAML retains every scientific, sampling and filtering
parameter from the archived manuscript configuration. Only input/output paths,
model location and the equivalent portable reference-catalog path are adapted.
The original configuration, default prediction configuration, dependency
specifications, model weights, reference content and program behavior remain
unchanged. The only Python-source edit is the package version string.

The stored models require TensorFlow 2.10.1/Keras 2.10.0. The existing modern
TensorFlow extras/top-level training requirements are not compatible with these
checkpoints; use the pinned prediction environment or Docker instructions.
Dependency specifications are archived; dependency binaries are fetched during
installation/build. Genome FASTA/FAI, annotations, user sample data, Dorado and
modkit executables must be provided separately.

## Privacy, LFS and redistribution review

The current candidate's tracked contents and decompressed reference archives
were scanned for credential signatures, private keys and unexpected sensitive
filenames. A pattern scan cannot establish the absence of every possible secret;
the checks and any concrete findings are recorded in the archive audit. Historical
local filesystem paths in original provenance/run metadata are retained; these
are provenance, not dependencies on an accessible workstation. The reference
data describe public cell-line or mouse sites, not supplied patient-level reads.

Manuscripts, raw reads, genome files, training tensors, generated results,
environments, credentials and the five pre-existing untracked work items remain
outside the candidate. The four mouse archives are not needed for the human
paper but support the documented mouse importer, so they were retained.

The candidate is checked for Git LFS pointer signatures and for the actual model
and reference payloads/checksums. No `.gitmodules` or LFS tracking rules are
present. Release contents are verified from the staged Git tree using
`git archive`, not from an unrestricted copy of the working directory. Checks
cover included dependency files and Docker `COPY` inputs as well as source,
model and reference files. No release-publishing workflow is tracked.
